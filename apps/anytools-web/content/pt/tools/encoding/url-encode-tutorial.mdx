## O que é codificação de URL

URLs são restritas a um pequeno conjunto de caracteres ASCII. O RFC para sintaxe de URL — [RFC 3986](https://datatracker.ietf.org/doc/html/rfc3986) — reserva um punhado de caracteres (`/`, `?`, `#`, `&`, `=`, etc.) para significado estrutural e proíbe espaços, caracteres de controle e a maioria de bytes não-ASCII de aparecer literalmente. **Codificação de URL** (também chamada *codificação de percentual*) é o mecanismo de escape: cada byte proibido é substituído por `%` seguido por seu valor hexadecimal de dois dígitos.

Portanto, um espaço se torna `%20`, um ampersand `%26`, um caractere chinês `世` se torna `%E4%B8%96` (seus três bytes UTF-8, cada um percent-encoded). O resultado é sempre ASCII-safe.

## `encodeURIComponent` vs `encodeURI`

JavaScript expõe duas funções diferentes, e elas não são intercambiáveis:

- **`encodeURIComponent`** codifica *tudo* que não é um caractere não reservado. Use isso para **uma peça** de uma URL — um valor de parâmetro de consulta, um segmento de caminho, um campo de formulário.
- **`encodeURI`** preserva caracteres estruturais de URL (`:/?#&=+$,`) na suposição de que você está entregando uma URL completa, já estruturada. Use isso quando você tem uma URL completa com conteúdo não-ASCII e quer torná-la transport-safe sem quebrar sua estrutura.

Exemplo de escolha errada: se você `encodeURI("a=1&b=2")`, o `=` e `&` são preservados como está — OK se essa string é uma consulta, quebrada se é um *valor* destinado a conter `=` ou `&` literal.

Esta ferramenta oferece ambas, além de um modo de decodificação que aceita ambos os sabores.

## A pegadilha `+`

Historicamente, formulários HTML codificam espaços como `+` (este é o tipo MIME `application/x-www-form-urlencoded`). Padrões de URL modernos codificam espaços como `%20`. Ambos estão por aí — ao decodificar uma string de consulta, você deve aceitar ambos. Nosso decodificador faz.

Quando *codificando*, sempre emitimos `%20` (o padrão moderno). Não emita `+` para espaços a menos que você especificamente precise de compatibilidade form-encoded.

## Exemplos

| Entrada | encode component | encode full URL |
|---|---|---|
| `hello world` | `hello%20world` | `hello%20world` |
| `a=1&b=2` | `a%3D1%26b%3D2` | `a=1&b=2` |
| `https://x.com/a?b=1` | `https%3A%2F%2Fx.com%2Fa%3Fb%3D1` | `https://x.com/a?b=1` |
| `café` | `caf%C3%A9` | `caf%C3%A9` |

## Quando você usará isso

- Construindo strings de consulta programaticamente sem um roteador/biblioteca.
- Inspecionando uma URL codificada que alguém colou para você.
- Debugando "por que meu backend vê `+` em vez de espaço?"
- Gerando URLs canônicas em sitemaps e `<link rel="canonical">`.

## Privacidade

100% no navegador via nativas funções `encodeURIComponent` / `decodeURIComponent`. Nenhuma solicitação de rede, nenhum log.

## Ferramentas relacionadas

- **Base64 Encoder** — codificação diferente, geralmente encadeada com codificação de URL para transporte compacto.
- **Slugify** — transformar texto arbitrário em slugs de URL segura (uma operação de nível mais alto do que codificação simples).
